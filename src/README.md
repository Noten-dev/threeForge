# ThreeForge Engine v2.6.0 — комплект для интеграции

Игровой движок поверх **three.js r186**: единый ESM-файл без других зависимостей.
Процедурный мир «под ключ»: игровой цикл с фиксированным шагом, дневной цикл и CSM-тени,
туман, погода, частицы (GPU/CPU), потоковый террейн с растительностью и водой, небо и облака,
физика тел, ввод, звук, постобработка (SSAO/TAA/bloom/god-rays/FXAA), куллинг, LOD, инстансинг.

> **v2.7 Shadow Overhaul** — глубокая переработка теней: каскады CSM 1–4 с настраиваемыми
> сплитами/весами тайлов, генерируемый PCF (тиры тапов 4–64, soft-режим с contact-hardening-
> аппроксимацией), туманный фейд для всех источников, плавные ночные тени + тени луны,
> бюджет обновлений `LightManager`, пресеты `applyShadowQuality('ultra', …)`, отладочный
> `SunShadowHelper`. Дефолты совпадают с v2.6 — детали в [CHANGELOG.md](CHANGELOG.md),
> рецепты в [QUICKSTART.md](QUICKSTART.md#85-тени-v27-shadow-overhaul).

## Быстрый вход (для агента)

1. Прочитать **QUICKSTART.md** — TL;DR и раздел «Подключение» (import map / npm).
2. Поставить `three@0.186.0` (ровно r186 — модуль опирается на `THREE.Timer` и внутренние shadow-классы).
3. Импортировать нужное из `threeforge-v2_6_0.js`; детали конкретных классов — в **API.md** (у каждого экспорта указан номер строки в файле движка).
4. Системы подключаются в `Engine` через `addSystem({ fixedUpdate?, update? }, priority)`; `PostPipeline` — через `attach(engine)`; `PhysicsWorld.step(dt)` оборачивается в `fixedUpdate`.

## Гарантии очистки

> **v2.8 Gameplay Kit** — игровой набор: FP-контроллер, вьюмодель (кулак+меч), scatter-пропсы,
> процедурные меч/кулак/цветок (+тип детали `flower`), парящие острова, stylized-материалы
> (toon+rim), кино-грейд постобработки, DOM-HUD. Демо: `examples/sword-field.html`
> (запуск `npm run serve`); тесты: `npm run smoke` (база), `npm run game` (105 проверок),
> `npm run shadow` (74), `npm run shaders` (49 GLSL).
> Single-file вариант демо (открывается двойным кликом, без сервера) собирается
> командой `npm run standalone` в `examples/sword-field-standalone.html`
> (артефакт в git не кладётся).

> **v2.9 Horizon & Contact-AO & Day fix** — три визуальных/рендерных фикса с полными
> разборами в [PLAN-fixes.md](../PLAN-fixes.md): **H1** вуаль горизонта неба
> (непрерывность тумана на силуэте, `SkyDome.bindFog`); **S1–S4** SSAO как контактная
> подсветка стыков (квадратичный спад по дистанции окклюдера, плотные дефолты,
> применение только к ambient-составляющей через `uAOAmbient`/`ao.lights`) — исчезли
> «обволакивающие» ореолы вместо теней; **D2** дневной режим с CSM: shadow-map луны
> существует с первого кадра (`needsUpdate`), иначе PCF/PCFSoft ловил
> GL INVALID_OPERATION на всех draw освещаемых материалов. Демо восстановлено,
> headless-скриншоты до/после — `npm run shot`, доказательства в `shots/`.

> **Примечание v2.7:** в файл движка внесён Shadow Overhaul (метки SH1..SH9 в
> CHANGELOG) — токен-поток больше не совпадает с оригиналом v2.6.0; проверка
> `tools/validate.mjs` применима только к исходной очищенной сборке. Качество
> v2.7 обеспечивается dev-стендом: `npm run shaders` (46 GLSL-комбинаций через
> glslang) и `npm run smoke` (67 логических проверок, включая покадровую
> эквивалентность дефолтных CSM эталону three).

Очищенная сборка получена удалением комментариев через AST (acorn):
- токен-поток совпадает с оригиналом **токен-в-токен** (97 982 токена), список из 167 экспортов идентичен;
- строковые литералы и GLSL-шейдеры не затрагивались;
- сохранены все 106 JSDoc-комментариев (`/** … */`) у классов, методов и функций;
- удалены: changelog-шапка (спасён в CHANGELOG.md), баннеры разделов, inline-заметки и метки фиксов;
- модуль импортируется и проходит smoke-тест в Node 20 + three@0.186.0.
